# Crewmind website: owner inputs and go-live checklist

Updated: 2026-10-19. Status: prelaunch. Copy improvements do not make the website launch-ready. Check an item only when its acceptance evidence exists. This document does not authorize publishing, collecting data, spending money, or enabling tracking.

## How to use this list

Start with Section 1. Provide only approved public material in this repository. Share credentials through a suitable secure channel, never in this document, chat transcripts saved here, or source code. Private operational records and customer information must remain outside the product handoff.

“Required” means needed for this site's intended lead-generation launch. “Conditional” applies only if that feature, channel, jurisdiction, or claim is used. “Recommended” improves trust or learning but is not a universal launch requirement. A genuine portrait, public fixed prices, testimonials, analytics, and a connected demonstration are not mandatory prerequisites to publishing an honestly described service website.

## 3. Request journey: required before promoting the offer

- [ ] Choose the simplest workable contact route using O3. A reliable booking or contact link can be sufficient; a custom form is not compulsory.
- [ ] If retaining a form, agree the minimum necessary fields. Review whether business name, website, and both long text questions are necessary.
- [ ] Implement validation, accessible labels, helpful error states, pending state, duplicate handling, and an honest confirmation.
- [ ] Test successful receipt at the real destination, delivery failure, invalid inputs, unavailable provider, and repeated submission. Do not claim receipt before delivery is established.
- [ ] Confirm who receives requests, who can access them, how to respond, and how to remove records under the actual retention policy.
- [ ] Add appropriate abuse protection and keep provider credentials server-side if a delivery service is used.
- [ ] If booking is selected, verify time zones, availability, cancellation/rescheduling, and confirmation. A request must not imply a reserved pilot.
- [ ] Publish matching privacy information before collecting data. Review actual dependencies and providers, not a generic template.
- [ ] Enable the new journey deliberately and replace every “requests are not yet open” notice in the same release. Re-test all CTAs and FAQs.
- [ ] Keep original captured recruitment submissions, tracking, and authentication blocked permanently.

## 4. Delivery readiness: required before accepting a pilot

- [ ] Complete O5–O8 and establish a repeatable discovery/scope process.
- [ ] Agree a baseline, expected live activity, review owner, success measures, exceptions, and the seven-day assessment start.
- [ ] Define what happens if activity is too low to judge value. Additional time or scope must be agreed; never imply automatic extension.
- [ ] Test real integrations for the actual agreed pilot, including duplicate events, unavailable tools, failed messages, approvals, and human fallback.
- [ ] Agree access permissions and data handling before connecting customer tools; keep credentials and customer records outside this repository.
- [ ] Confirm any voice, recording, messaging, or automated-contact requirements for the actual channel and market before use. This checklist is not a jurisdiction-specific legal opinion.
- [ ] Review paid continuation and exit choices with the customer before any paid commitment. Record consent through the agreed operational process, not this public repository.

## 8. First weeks after launch

- [ ] Monitor request receipt and failures, broken links, provider limits, and builder response coverage.
- [ ] Ask early prospects what task they recognized and what stopped them from enquiring.
- [ ] Use observed pilot activity to improve examples; get permission before publishing customer material.
- [ ] Track recurring objections about price, scope, security, and ongoing access; revise copy from evidence.
- [ ] Evaluate a narrower audience or alternative CTA only when real buyer feedback or sufficient traffic supports comparison.

## Release decision

Do not call this a final lead-generation website while its only request route is disabled. Copy can be complete before operations are complete. Launch requires an accountable public identity, a working contact route, accurate commercial/data arrangements, approved presentation, production verification, and explicit publication authorization. Public fixed pricing, analytics, a portrait, testimonials, and a connected public demo remain optional unless the chosen claims or journey depend on them.
